## Added
* **Oracles for two tests that could not fail** (`tests/unit/core_AsyncRecorder_test.cpp`, `tests/unit/core_NetlistCsv_test.cpp`): the byte-shuffle codec was covered only by a round-trip test (titled, accurately, "is a bitwise involution") — which passes whenever `byteShuffle` and `byteUnshuffle` implement *the same wrong permutation*, because it never checks what the permutation is. It is now pinned against a hand-computed 3×4 byte-plane expectation, and against the property the transform exists for: after shuffling smoothly-varying doubles, the plane holding the shared sign/exponent byte must be a constant run while the low-order plane must not, and the output must be a permutation of the input multiset. Demonstrated rather than asserted: reversing the plane order in *both* directions (still a perfect mutual inverse) leaves the old involution test green and turns both new tests red. Separately, `parseValue`'s entire exponent branch was unexercised even though pandas writes connection resistances as `1e-05`, so a liionpack `netlist.to_csv()` is exactly the input nobody tested; scientific notation is now pinned by exact value (`1e-05`, `1.5E+03`, `2.5e2`) and truncated exponents (`1e`, `1e+`, `1e-`, `1e+x`, `1.e5e5`) are pinned as atomic rejections. Disabling the exponent branch turns the new test red. Both binaries grew (`463 → 471`/`10 → 12` and `800 → 821`/`7 → 9`); the other 51 are digit-identical.
* **9C-6 line-debt sweep** (`src/core/{SpmBatch,RecordingFormat,AsyncRecordingCodec,PackSolverIterative}.cpp`, `src/core/{SpmDiffusionRhs.hpp,detail/CheckedArithmetic.hpp,detail/AsyncRecordingFormat.hpp}`, `scripts/slide_coverage/`): the four oversized translation units are split along boundaries that turned out to be real, not line-count cuts. `SpmBatch.cpp` reaches its implementation only through type-erased pointers, so it does not include `SpmPipeline.hpp` at all; `PackSolver`'s ladder and relaxation strategies never touch the Eigen factorisation, which is exactly why they can move; the recorder's binary writer and reader stay together because they must agree byte for byte. `checkedAdd`/`checkedMultiply` existed twice with identical semantics and now have one definition. The 1,281-line coverage reporter is a package (scan → session → classify → report) behind the same CLI. Only two `src/core` files still exceed 700 lines, both with recorded justifications: `SpmPipeline.hpp` (745; a template that cannot be split without destroying the zero-overhead composition) and `CyclerV2.cpp` (771; the M0.7 exception).

## Fixed
* **Ladder detection was O(cells²)** (`src/core/PackTopology.cpp`): the series-parallel ladder walk resolved each cell to its branch with a `std::find_if` over *every* branch, inside a loop over every cell — so `compile()` cost grew quadratically in pack size, against a project whose stated target is 10⁴–10⁵ cells (PLAN.md §1). It now builds a `cell → first branch` index once and looks up in O(1). `try_emplace` keeps the first match, exactly like the `find_if` it replaces, so a duplicated cell id still resolves to the same branch; the index is built *after* every early return, so a pack that is not a ladder pays nothing for it; and it is a hash map rather than a vector indexed by cell id, because sizing an allocation from an input-derived maximum is the amplification shape D-29 already had to fix once. All 53 binaries digit-identical.
* **PC-10 violation: the Arrhenius exponent was hand-rolled in three ageing kernels** (`src/core/{Sei,Lam,LithiumPlating}.hpp`): `spm_scalar::arrheniusFactor` (`SpmScalarKernels.hpp:111`) is the declared single owner of `(1/T_ref − 1/T)/Rg`, and nine sites already call it — including `CudaSpmRuntime.cu`, which is the entire point of the one-physics-source contract. The three ageing headers spelled the expression out by hand instead, so a correction to the shared kernel would have silently missed them. They now call it, with the `static_cast<Real>` argument form already established in `SpmObservables.hpp`, and each header includes `SpmScalarKernels.hpp` explicitly rather than reaching it transitively (the M0.9 include-order defect class). Digit-identical for the `Dual` instantiation too, and provably so rather than by hope: `Dual` declares only `operator/(Dual, Dual)`, so the hand-rolled form was *already* performing the implicit `double → Dual` conversion the cast now makes explicit. Verified: all 53 binaries digit-identical to baseline, CTest 58/58. `SurfaceCrack.hpp` is deliberately **not** included — it writes the factor in a different association (`k_act/Rg · (1/T_ref − 1/T)`), so routing it through the helper would change the last bits; it is recorded as remaining PC-10 debt rather than silently reassociated.
* **Test binaries no longer depend on the directory they are launched from** (`CMakeLists.txt`, `src/settings/slide_paths.hpp`): `slide_paths.hpp` has always carried a `#ifdef SLIDE_ROOT_DIR` escape hatch, but **nothing in the build system ever defined that macro**, so every build silently took the `"../.."` fallback and resolved `data/` and `results/` against the *current working directory*. The symptom was that 25 of the 53 Catch2 binaries failed with `File ../..\data\Kokam_OCV_C.csv could not be opened` when a developer ran them directly, while CTest passed 58/58 — CTest happens to run them from `<build>/bin`, which is exactly two levels below the repo. The build now defines the macro (directory scope, so the legacy sub-libraries — `PRIVATE` dependencies of `src` — and the sibling test tree all receive it; excluded from `SLIDE_CORE_ONLY` so wheel/WASM/consumer builds stay relocatable). Registered before the change and confirmed after: running all 53 binaries from the repo root goes from **25 failing to 0**, with every assertion count digit-identical to baseline and CTest still 58/58.
* **`PathVar` paths are one shared immutable object instead of a mutable per-TU copy** (`src/settings/slide_paths.hpp`): `results` and `data` were namespace-scope `static` — a separate dynamically-initialised copy in every translation unit including the header, and non-`const`, so a write would have silently changed only the writing TU's view. They are now `inline const`. Nothing in the tree assigns to them, and no namespace-scope object is constructed from them, so there is no static-initialisation-order exposure.
* **The core library and its warning policy were never connected** (`src/core/CMakeLists.txt`): `cmake/CompilerWarnings.cmake` defines a careful warning set, but `project_warnings` had no consumer among the library targets — `slide_core` and all 53 `tests/unit` binaries compiled with **no `-W` flags at all** (only `slide`, the benchmarks, `tests/integration`, and `tests/core_only` were covered). `slide_core` now links it `PRIVATE` (the policy is ours to keep, not something downstream consumers inherit). Measured before enabling: the core was already clean apart from a single `-Wshadow`, so enforcement was free; all 22 core translation units now rebuild with **0 warnings, 0 errors**.
* **Shadowed `derivative` in the custom-differential control branch** (`src/core/CyclerV2.cpp`): a local `real_t derivative` shadowed the outer `const auto derivative = batch_->derivative().raw()` span declared ~120 lines above — the same identifier meaning "the scalar d(current)/dt returned by the user's control function" in one scope and "the batch's derivative state rows" in the enclosing one. Renamed to `current_derivative`; behaviour unchanged.
* **Boost headers are included as `SYSTEM`** (`cmake/recipes/boost.cmake`): Eigen and range-v3 were already `SYSTEM`, Boost was not, in either the installed-Boost or downloaded-header branch. Its diagnostics accounted for 61 of the 187 unique warning sites seen when compiling the test tree under the project policy. Dependency noise is what motivates blanket `-Wno-*` suppressions, and those suppressions are what hide real warnings in SLIDE's own code.
* **Strict JSON reuse and allocation Status boundaries are atomic and auditable** (`src/core/StrictJson.cpp`, `ParameterSet.cpp`, `CyclerV2.cpp`): strict JSON now parses into a local DOM and move-publishes only after complete success, so reused outputs cannot retain stale nodes or be partially overwritten on rejection. Equivalent `bad_alloc`/`length_error` handlers delegate to one mutation-tested Status mapper per TU while structural checks preserve both exception types, callback rethrows, and run rollback. A valid NCH8 replacement of a configured NCH5 batch also proves stale Cycler scratch rejects before copying or stepping, preserves both arenas and every solution field, and recovers after reconfiguration.
* **Cycler runs are allocation-atomic across every public arena** (`src/core/Experiment.*`): drive-cycle ownership is copied inside a caught `Status` transaction, missing static drive references are preflighted, and each run snapshots both padded state and derivative arenas in configured scratch. `bad_alloc`/`length_error` now restore the pre-run snapshot and leave caller output untouched, while ordinary callback/solver failures keep their coherent partial-error solution and per-step rollback. (P0-C6)

They are now per-call locals. (bug A2)
* **Parallel-solver Jacobian is refactorised every iteration.** The LU factorisation was computed once from the initial resistance estimate and never refreshed even though the secant estimates update each iteration, degrading Newton to a slow/failing chord iteration. The Jacobian is now rebuilt from the updated estimates and refactorised each iteration. (bug A3)
* **Contact-resistance heat (`Module_p` `Qcontact`) no longer double-counts.** The cumulative branch-current accumulator was declared outside the per-resistor loop and never reset, so the contact heat grew quadratically. Each contact resistor now correctly sees the summed current of the cells behind it. (bug A4)

* **Analytical parallel-branch solver** returns `Status::Invalid_SUs` instead of dereferencing an unchecked `dynamic_cast` when a child is not a `Cell_ECM<1>`. (bug A5)
* **Parallel-solver early-exit residual** uses a proper L∞ norm (`max`) instead of a malformed running sum of maxes. (bug A7)

The `#include "CellDataWriter.hpp"` was also moved out of `namespace slide` to global scope — the mid-namespace include pulled standard headers into `namespace slide` and nested `slide::slide::CellDataWriter`, so the header could not compile when included. (bug B1)
* **`Histogram::add()` no longer writes out of bounds** on a default-constructed histogram (empty bins): it returns early when there are no bins. Affects `slide::EmptyHistogram` and any histogram used before `initialise()`. (bug B2)
* **`Cycler::CC` energy throughput (`Wh`) is now actually accumulated**, integrating with the trapezoid rule `(v_before + v_after)/2` per step. Previously it multiplied by a `vi` sample that `Cycler::setCurrent` never assigned, so CC energy throughput was always 0 Wh. (bug B3)
* **SEI degradation-model documentation aligned with the code**: the unreachable-model message now says ids "0 to 4" (cases 0–4 exist); the inline literature references for SEI ids 1 and 2 were swapped relative to the formulas (id 1 = kinetics-limited/Ning & Popov, id 2 = kinetics + SEI-layer diffusion/Pinson & Bazant); `DEG_ID` now documents id 4. No behavioural change. (bug B4)
* **Degradation forward-Euler invariant documented and debug-guarded** in `Cell_SPM::timeStep_CC`: the loop integrates every state index (including the algebraic I/V slots) and is only correct because degradation leaves those derivatives at 0 — now asserted in debug builds. Digit-identical behaviour. (bug B5)
